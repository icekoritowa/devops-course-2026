# Git и SVN

1. Ветка Git — ссылка на коммит; её создание почти не зависит от размера проекта. В SVN ветка обычно является копией каталога в репозитории. Это серверная cheap copy: данные немедленно не дублируются, поэтому утверждение, что само создание ветки SVN всегда дорогое, неверно. Дополнительные затраты связаны с сервером, сетью и организацией merge.
2. Для commit в SVN нужен доступ к серверу репозитория. Интернет не обязателен, если сервер локальный или в локальной сети. При недоступном удалённом сервере можно менять файлы, но нельзя зафиксировать серверную ревизию. Git делает коммиты локально.
3. SVN подходит существующим инфраструктурам, требующим прав доступа к отдельным каталогам, централизованного контроля и блокировок крупных бинарных файлов. Он не ограничивается устаревшими проектами.
